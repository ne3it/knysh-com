# Фикс: мобильное меню раздела WB не прокручивается до конца

## Проблема
На телефоне список из 14 функций в разделе `/wb` нельзя прокрутить до нижних пунктов
(«Сплит», «Экосбор», «Указ 243», «ФСЗН», «Анализ покатушек»).

Причина в `src/components/layout/SectionSidebar.tsx:62`:
`<aside className="fixed left-0 top-0 z-40 h-screen ...">`.
`h-screen` = `100vh`, а на мобильных браузерах `vh` учитывает только «большую» область
(без скрытого URL-бара). Фактическая видимая область меньше, поэтому нижний край списка
оказывается под адресной строкой, а внутренний скролл `nav` (`overflow-y-auto`,
`SectionSidebar.tsx:114`) не может показать этот край — визуально «список обрывается».

Дополнительно: при открытом drawer фон под меню продолжает скроллиться
(нет блокировки `body`), и нет учёта `safe-area-inset-bottom` у iPhone с home-индикатором.

## Задачи

1. `src/components/layout/SectionSidebar.tsx`
   - Заменить `h-screen` на `h-[100dvh]` (с фолбэком для старых браузеров):
     `h-screen h-[100dvh]` — старые получают `100vh`, поддерживающие dvh перекрывают его.
     Tailwind 3.4 (см. `package.json`) поддерживает `100dvh`.
   - К `nav` (`flex-1 overflow-y-auto p-3`) добавить:
     - `overscroll-contain` — не «прокидывать» скролл на страницу;
     - `pb-[calc(0.75rem+env(safe-area-inset-bottom))]` вместо `p-3`, чтобы
       последний пункт не уходил под home-индикатор iOS;
     - `-webkit-overflow-scrolling: touch` (iOS momentum-скролл) — добавить в
       `style jsx global` в `SectionLayout.tsx` рядом с существующими `.sidebar-scroll`
       правилами (либо инлайном через arbitrary-класс, если prefers-reduce-motion блок
       уже содержит глобальные правила — важно не дублировать селектор).

2. `src/components/layout/SectionLayout.tsx`
   - Блокировать скролл `body` при `mobileMenuOpen === true`: в существующий
     `useEffect` для Escape/resize добавить `document.body.style.overflow = 'hidden'`
     и восстановление в cleanup. Существующий effect уже early-return-ит при
     `!mobileMenuOpen`, поэтому блокировка будет активна ровно при открытом drawer.
   - Обёртке drawer (`SectionLayout.tsx:103`) заменить `inset-y-0` на
     `inset-y-0` + `h-[100dvh]` не нужно — она уже по inset; проверить, что
     `h-[100dvh]` на `aside` согласован с `inset-y-0` обёрткой (достаточно
     оставить обёртку как есть).

3. Проверка, что на desktop (`lg`) ничего не изменилось: `h-[100dvh]` на десктопе
   равен `100vh`, но для консистентности можно добавить `lg:h-screen`.

## Вне области
- Редизайн/компактность пунктов, разбиение на группы, автоскролл к активному пункту.
- `SectionLayoutWithHeader` (не используется в `/wb`) — не трогать.
- Десктопный сайдбар в свёрнутом виде.

## Валидация
1. `npm run lint`
2. `npx tsc --noEmit`
3. Ручная проверка в dev (`npm run dev`): `/wb` на ширине 375px и 320px —
   открыть меню, доскроллить до последнего пункта, он должен быть полностью виден
   над home-индикатором; фон не скроллится; закрытие по крестику и по Escape
   возвращает скролл страницы.
4. Проверить iOS Safari (где и воспроизводится проблема) при свернутом/раскрытом
   URL-баре, а также Android Chrome.
5. Проверить десктоп 1440px: сайдбар не изменился.
